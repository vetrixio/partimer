# 打工人計時器（partimer）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出 macOS／Windows／Ubuntu 24.04+ 共用一套程式碼的系統匣打卡 app，核心邏輯完整測試，GitHub Actions 打包發佈。

**Architecture:** Cargo workspace：`crates/partimer-core`（純 Rust，不依賴 Tauri；資料、存讀檔、計時、統計、CSV、草稿與狀態機都在這裡，全部可測）＋ `src-tauri`（Tauri 2 殼：系統匣、視窗、快捷鍵、平台差異，只做轉接）＋ `src/`（Svelte 5 單一前端，依視窗 label 決定畫面）。後端是唯一的狀態來源，前端只顯示與送指令；輸入框不受後端狀態控制，以 `draft.generation` 決定何時重建。

**Tech Stack:** Rust 1.98（edition 2024）、Tauri 2、Svelte 5、TypeScript、Vite、serde/serde_json、chrono、uuid、dirs、thiserror；測試用 chrono-tz、tempfile。

**Spec:** `docs/superpowers/specs/2026-11-06-partimer-design.md`（每個 task 都要對照 spec 的對應章節，本計畫只寫 spec 沒決定的事）

## Global Constraints

- 平台：macOS、Windows 10/11、Ubuntu 24.04+；其他 Linux 不保證。
- 顯示名稱「打工人計時器」；內部名稱 `partimer`（資料夾、執行檔、安裝檔檔名、`.deb` 套件名、指令）；identifier `com.vetrixio.partimer`。
- 資料夾 = `dirs::data_dir().join("partimer")`（**不要**用 Tauri 的 `app_data_dir`，它會用 identifier 當資料夾名）。
- 相依套件只能用 spec §2 清單內的；其他一律先問使用者。版本釘死（Cargo 用 `=x.y.z`，npm 用 `save-exact`），選發佈超過 7 天的版本（npm 安裝加 `--before=<今天-7天>`）。安裝後跑 `npm audit` 與 `cargo audit` 並回報。
- 禁止 `npx -y`、`@latest`、`curl | sh`。
- 時間一律以 UTC 存，日期歸屬與顯示用本機時區；core 不得直接呼叫 `Utc::now()` 或 `Local`，「現在」與時區由呼叫端傳入。
- 時長 = 結束 − 開始 − 累計暫停，負值當 0；不得用計時器累加。
- 不可每打一個字就寫檔；草稿只進記憶體。
- 每個 task 結束前：`cargo test -p partimer-core` 全過、`cargo clippy --workspace -- -D warnings` 無警告；有前端變更時 `npm run check` 通過。失敗就停下來修，不提交。
- Commit message 用英文，不加任何 Claude／AI 署名。所有提交都在 `feat/partimer-v1` 分支。
- 畫面與平台行為無法自動驗證，每個 UI task 結束時把「需實機驗證」的項目加進 `docs/verification-checklist.md`，不可寫「應該沒問題」。
- 使用者看得到的文字全用繁體中文。

## Review Focus

1. **睡眠或時鐘跳動後的 12 小時提醒**：筆電蓋了一晚打開，有效時長突然超過 12h → 只提醒一次，不能每秒提醒；按「沒忘」後到 24h 才再提醒。測試在 Task 9（`long_running_reminder_fires_once_after_jump`）。
2. **連按兩次 STOP**（或 STOP 與快捷鍵同時觸發）：第二次必須回 `NotRunning`，資料與草稿都不變，不能產生新紀錄或清掉東西。測試在 Task 9（`double_stop_is_noop`）。
3. **重開 app 時已計時好幾小時**：整點提醒不可把過去每個整點一次補發；只從下一個整點開始。測試在 Task 9（`hourly_reminder_does_not_backfill_after_open`）。
4. **刪掉「上次使用的專案」或封存它**：面板預設專案要退回第一個未封存的專案（沒有就顯示新增表單），不可指向不存在的專案。測試在 Task 9（`selected_project_falls_back_when_last_deleted`）。
5. **夏令時間切換時填了不存在的本機時間**（編輯／補登／12h 結束時間）：回傳可讀錯誤，不可 panic。測試在 Task 2（`parse_local_input_rejects_dst_gap`）與 Task 9（`save_entry_reports_invalid_local_time`）。

### Task 2: 時區、時長與格式化

**Files:**
- Create: `crates/partimer-core/src/zone.rs`, `crates/partimer-core/src/duration.rs`
- Modify: `crates/partimer-core/src/testutil.rs`（加 `tz(name) -> Box<dyn LocalZone>`）

**Interfaces:**
- Produces:
  - `pub trait LocalZone: Send + Sync { fn to_local(&self, t: DateTime<Utc>) -> NaiveDateTime; fn from_local(&self, t: NaiveDateTime) -> LocalResult<DateTime<Utc>>; fn offset_label(&self, t: DateTime<Utc>) -> String /* "+08:00" */; }`
  - `pub struct SystemZone;`（用 `chrono::Local`）；`#[cfg(test)] impl LocalZone for chrono_tz::Tz`
  - `pub fn local_date(zone: &dyn LocalZone, t: DateTime<Utc>) -> NaiveDate`
  - `pub fn parse_local_input(zone: &dyn LocalZone, s: &str) -> Result<DateTime<Utc>, TimeInputError>`，格式 `YYYY-MM-DDTHH:MM`；夏令時間重複的時刻取較早者；不存在 → `TimeInputError::Nonexistent`；格式錯 → `TimeInputError::Format`。`Display`：「時間格式不正確」「這個時間因夏令時間切換而不存在」
  - `pub fn format_local_input(zone, t) -> String`（同上格式）、`pub fn format_hhmm(zone, t) -> String`（`"09:30"`）
  - `pub fn effective_seconds(e: &Entry, now: DateTime<Utc>) -> i64`
  - `pub fn round_minutes(secs: i64) -> i64`（四捨五入：`(secs + 30).div_euclid(60)`，負數先當 0）
  - `pub fn hours_decimal(minutes: i64) -> String`（整數運算：百分之一小時 = `(minutes*100 + 30) / 60`，輸出 `"1.50"`）
  - `pub fn format_hm(minutes: i64) -> String`（`"1h 30m"`、`"45m"`、`"2h 0m"`）
  - `pub fn format_hms(secs: i64) -> String`（`"01:23:45"`，超過 99 小時照樣顯示）

`effective_seconds`：結束點 = `end` 有值用 `end`；否則有 `pause_started_at` 用它；否則 `now`。結果 = `max(0, 結束點 − start − paused_seconds)`；計時中且未暫停時不扣進行中的暫停（沒有）。
