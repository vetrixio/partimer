- 標示說明：**〔使用者決定〕** 是使用者明確說的；**〔設計者決定〕** 是撰寫者的判斷，使用者可推翻；**〔實作者決定〕** 留給實作者自行判斷。

## 1. 這是什麼、為什麼要做

給接案工作者自己用的打卡記工時小工具。按一下開始計時，再按一下結束；每筆紀錄掛在「客戶 → 專案」底下，可寫標題與內容；月底匯出 CSV 對帳。

使用者用過前一版，踩了很多坑（見 §11），這一版的重點是：**時間一定記得對、輸入中文不會被打斷、STOP 之後不會污染上一筆或下一筆**。

### 目標

- 在 macOS、Windows、Ubuntu 24.04+ 上用同一套程式碼跑〔使用者決定〕。
- 開始／暫停／結束一鍵完成，當機、關機、蓋螢幕後都能正確接續。
- 計時中隨時看得到在計時（選單列文字或浮動小時鐘）。
- 月底能匯出 Excel 能直接開、中文不亂碼的 CSV。

### 不做（非目標）

算錢、時薪、請款單、帳號、雲端同步、跨裝置資料共享、手機版、番茄鐘〔使用者決定〕。只把時間記清楚。

也不匯入前一版的資料〔使用者決定〕，新版從空資料開始。§9.3「少欄位用預設值補」是為了本 app 日後版本升級時的相容性。

### 反目標（做到了也算失敗的情況）

- 計時中打中文會被打斷選字。
- 產生大量「只有幾秒、內容是上一筆摘要」的垃圾紀錄。
- 任何情況下資料檔被覆寫成空的或壞掉而無法還原。
- 存檔失敗導致 app 當掉。
- 啟動時自己跳出視窗。

## 3. 視窗與入口

### 3.1 系統匣／選單列圖示

| 平台 | 行為 |
|---|---|
| macOS | 選單列圖示 + 計時中在右邊顯示「時:分」（圖示與數字間留空隙）。左鍵點擊開關打卡面板。不顯示 Dock 圖示。 |
| Windows | 右下角系統匣圖示。左鍵點擊開關打卡面板。系統不支援圖示旁顯示文字，改為**滑鼠移上去顯示提示**：「計時中 1:23・專案名」／「暫停中 ⏸ 0:47・專案名」／「打工人計時器」。 |
| Ubuntu | AppIndicator 系統匣（Ubuntu 預設有擴充套件）。AppIndicator **不會把左鍵點擊傳給 app**，所以點圖示一律出現選單：「打開面板／紀錄／設定／結束」。計時中嘗試用 label 顯示時間，有些桌面環境不顯示，不保證。 |

圖示狀態（角色：小盆栽，見 §3.5）：

- 沒在計時：盆栽休息（葉子下垂、閉眼）。
- 計時中：盆栽醒著、葉子左右搖擺（切換 2–4 張圖做動畫），旁邊顯示時:分（macOS／可行時的 Ubuntu）。
- 暫停中：盆栽休息的樣子，時間前加 ⏸。

### 3.2 浮動小時鐘（新增，取代 Windows／Ubuntu 上無法顯示的圖示文字）

〔使用者決定〕Windows 上要一個半透明、浮在所有視窗之上的小東西。〔設計者決定〕三平台都做，用設定開關：

- 預設：Windows、Ubuntu **開啟**；macOS **關閉**（選單列已能顯示時間）。
- 外觀：約 130×40 的膠囊，左邊小盆栽（計時中會搖），右邊「1:23」；暫停中顯示休息的盆栽與「⏸ 0:47」。
- 無邊框、透明背景、永遠在最上層、不顯示在工作列／Dock、所有虛擬桌面都看得到。
- 平時半透明，透明度可在設定調整（40%–100%，預設 60%）；滑鼠移上去變不透明。
- 可拖曳；拖曳結束時記住位置（寫入設定）。位置若在目前所有螢幕之外，重置到主螢幕右上角。
- 點一下（非拖曳）開關打卡面板。
- 沒在計時時預設隱藏；設定可改為「一直顯示」（顯示休息的盆栽、不顯示時間）。
- 已知限制：獨佔全螢幕遊戲會蓋過它（Windows 限制，不處理）。
- Ubuntu：Wayland 不允許 app 自己置頂與指定位置，因此 **Linux 上啟動時若未設定 `GDK_BACKEND`，就設成 `x11` 走 XWayland**，讓置頂與位置記憶可用。

### 3.3 打卡面板

**只有一個面板視窗**，三種叫出方式都打開同一個：點圖示、全域快捷鍵、再開一次 app。

- 從圖示點開：出現在圖示附近（Ubuntu 無法得知圖示座標，置於螢幕右上角）。
- 從快捷鍵或再開一次 app 叫出：出現在螢幕中央偏上，浮在最上層，取得焦點。
- 快捷鍵再按一次收起。點圖示再點一次收起。
- 失去焦點時是否自動收起〔實作者決定〕，但不可在輸入法選字視窗出現時誤收起，草稿也不能因此遺失。
- 面板收起是隱藏，不是銷毀；草稿無論如何都保留（見 §5.4）。

### 3.4 紀錄視窗、設定視窗

一般視窗（有標題列，可縮放），**按了才建立**，關閉即銷毀。重複按只聚焦既有視窗。

### 3.5 視覺風格

〔使用者決定〕角色是「小盆栽」：工作時葉子挺起左右搖，休息與暫停時葉子下垂、閉眼、旁邊一個 z。陶土色花盆上有臉。視窗介面配色延續溫暖、柔和的感覺〔實作者決定細節〕。

美術素材由實作者以 SVG 繪製，再轉出各尺寸 PNG／ICO／ICNS〔設計者決定〕，使用者在實機驗證時看過再調整。示意圖的 SVG 要複製到 `assets/design/plant-mockup.svg` 進版控當參考。需要的素材：

- 系統匣圖示 16px、32px（含 @2x），休息 1 張、醒著搖擺 2–4 幀。
- macOS 選單列在亮色與暗色選單列上都要清楚（彩色圖示加深色外框，或分別出亮／暗版）。
- 浮動小時鐘用的盆栽（醒著動畫、休息）。
- app 圖示與安裝檔圖示（三平台需要的所有尺寸）。

### 3.6 啟動與單一實例

- 啟動時**不顯示任何視窗**（浮動小時鐘例外：若上次關閉時正在計時或暫停，且小時鐘開啟，就顯示它）。
- 第二次啟動 app：不開新實例，改叫出打卡面板（浮在最上層）。

### 3.7 全域快捷鍵

- 預設：Windows／Ubuntu `Ctrl+Alt+P`，macOS `Ctrl+Option+P`〔設計者決定〕。v1 不提供自訂。
- 註冊失敗（被占用、Wayland 不支援）時，在設定視窗以紅字說明，並教替代方案。
- Ubuntu 在 Wayland session 下（即使 app 走 XWayland），快捷鍵可能「註冊成功但按了沒反應」，因此要偵測 Wayland session（`XDG_SESSION_TYPE=wayland` 或有 `WAYLAND_DISPLAY`），偵測到就直接在設定視窗顯示紅字說明，不依賴註冊結果。
- **Ubuntu（Wayland）替代方案**：在「設定 → 鍵盤 → 自訂快捷鍵」新增一組執行 `partimer` 的快捷鍵；因單一實例機制，效果等於叫出面板。寫進使用說明。

## 4. 打卡面板內容

由上到下：

1. **提示列**（有才顯示）：從備份還原、存檔失敗重試中、12 小時提醒等。
2. **專案選單**：依客戶分組，封存的不列。預設上次使用的專案。最下面一項「＋ 新增專案…」，展開表單輸入客戶名與專案名；客戶名與既有客戶相同（去掉前後空白後完全相同）就併入。**沒有任何專案時，面板直接顯示新增專案表單。**顏色以選單外的色點顯示（例如選單左邊一個圓點），**不可把色塊放在選單選項裡**。
3. **大字計時**：時:分:秒，每秒更新（由時間戳計算，見 §6）。
4. **標題**（單行）：未計時時預填「這個專案最近一筆紀錄的標題」（以開始時間最新者為準）；無則空白。預填只在「切換專案」「STOP 後」「app 啟動」時發生，不可覆蓋使用者已經在打的文字。
5. **內容**（多行，約 5 行高）：不預填。
6. **儲存列**（計時中才顯示）：「儲存」按鈕 + 狀態文字「尚未儲存／已儲存」。快捷鍵 Cmd+S（macOS）／Ctrl+S（其他）。
7. **按鈕列**：主按鈕 START／STOP；計時中左邊多一顆 PAUSE／RESUME。
8. **今日紀錄**：今天開始的紀錄（最新在上）＋正在計時的那筆（即使是昨天開始的，也一定列出），每筆顯示起訖、標題、專案、時長。下方今日總時數（含正在計時那筆的目前時長）。點一筆的行為〔實作者決定〕（建議：打開紀錄視窗並開啟該筆的編輯）。
9. **底部**：紀錄、設定、結束 app。

### 4.1 視窗大小

- 面板寬度固定（約 360px），**高度跟著內容變**（多了儲存列、提示列、今天多一筆都要長高），用量測內容後設定視窗大小的方式做。
- 最小高度保證主按鈕看得到；最大高度不超過螢幕可用高度，超過時只讓「今日紀錄」區塊捲動。
- 任何情況下不可開成 0×0 或寬高為 0。

### 4.2 計時中切換專案

選別的專案 → 確認「結束目前這筆，改記另一個專案？」→ 確認後：目前這筆以草稿的標題與內容存檔並在此刻結束 → 新專案立刻開始一筆（標題預填新專案的上次標題，內容空白）。取消則選單回到原專案。暫停中切換也一樣，但目前這筆的結束時間是按暫停那一刻（同 §6 暫停中 STOP 規則）。

### 4.3 12 小時提醒

計時中的有效時長（扣掉暫停）超過 12 小時：在面板顯示提示並發一次系統通知「是不是忘了停？」。提示中可選「實際結束時間」（日期時間選擇器，預設為開始時間 + 有效時長的某個合理值〔實作者決定〕，必須晚於開始且可以容納已暫停時間），按確認就用該時間結束；也可選「沒忘，繼續計時」，之後每再多 12 小時再提醒一次〔設計者決定〕。

### 4.4 整點提醒（新增，可選）

〔設計者決定〕設定裡「每整點提醒已計時時數」，預設關閉。開啟時，計時中每滿 1 小時有效時長發一次通知「已計時 N 小時・專案名」。暫停中不提醒。

## 5. 草稿與存檔流程（前一版踩坑的核心，務必照做）

### 5.1 不要每打一個字就存檔

標題與內容輸入時只更新草稿，**不寫檔、不讓輸入框因資料更新而重繪**。輸入框是非受控的（或受控但聚焦時絕不從外部覆寫值）。只有以下時機才把草稿寫進紀錄並存檔：

- 按「儲存」或 Cmd/Ctrl+S
- 按 STOP
- 計時中切換專案
- START（把開始前打的標題與內容寫入新的一筆）

### 5.2 先結束編輯再存再清

STOP、START、儲存、切換專案時：

1. 若輸入法還在組字（`isComposing`），等組字結束（`compositionend`）再處理，或直接忽略該次按鍵觸發的快捷鍵〔實作者決定細節〕。
2. 讓輸入框失去焦點。
3. **直接從輸入框讀當下的值**，連同動作一起交給後端的單一指令（例如 `stop(title, content)`），由後端一次完成「寫入標題內容＋結束」並存檔。不要分成「先存草稿、再停止」兩個非同步呼叫。
4. 後端回傳新狀態後，前端換成新的一筆；**輸入框整個重建**（以紀錄 id／「空白狀態序號」當 `{#key}`），不沿用舊的 DOM 節點。

### 5.3 STOP 之後的欄位不屬於剛結束的那筆

- STOP 後：標題換回「該專案最近一筆的標題」（也就是剛結束那筆的標題），內容清空。這時的欄位是「下一筆」的草稿，跟剛結束的那筆**沒有任何連結**。
- 結束後要補寫，一律到紀錄視窗編輯。

### 5.4 草稿放在 app 層級

- 草稿（標題、內容）存在 Rust 後端的記憶體狀態，前端在 `input` 事件時同步過去（只進記憶體，不寫檔）。面板隱藏再打開、甚至面板視窗被重建，草稿都還在。
- 草稿不寫入磁碟〔設計者決定〕；app 結束後未儲存的草稿會消失。計時中結束 app 時是否先自動儲存草稿〔實作者決定〕（建議：結束 app 時若有未儲存草稿，自動存入計時中的那筆）。
- 「尚未儲存／已儲存」= 草稿是否與計時中那筆已存的標題內容相同。
- 計時中那筆若在紀錄視窗被編輯並儲存：以紀錄視窗的值為準，草稿若沒有未儲存變更就跟著更新；若有未儲存變更，面板顯示提示「這筆已在紀錄視窗被修改」，草稿保留不覆蓋，讓使用者自己決定按不按儲存〔設計者決定〕。

## 6. 計時、暫停與時長規則

- 同一時間最多一筆在計時（未結束）。
- **時長 = 結束 − 開始 − 累計暫停**；計時中「結束」用「現在」；暫停中「結束」用「目前暫停的起點」。結果小於 0 時當作 0（時鐘倒退）。**不可用計時器累加秒數。**
- 蓋上螢幕、睡眠的時間一律算在內（所以需要 12 小時提醒）。
- 暫停：記下 `pauseStartedAt = 現在`。繼續：`pausedSeconds += 現在 − pauseStartedAt`（負值當 0），清空 `pauseStartedAt`。可以暫停很多次，始終同一筆。
- **暫停中按 STOP：結束時間 = `pauseStartedAt`**，該段暫停不加進累計。
- 暫停中關 app 或關機，重開後仍是暫停狀態（因為狀態完全存在資料檔裡）。
- 顯示：時長顯示到秒。**小計、合計與 CSV 以「每筆先四捨五入到分鐘」再加總**〔設計者決定，讓 CSV 的分鐘欄加總等於畫面合計〕；小數小時 = 分鐘 ÷ 60 四捨五入到兩位。
- 跨午夜：整筆算在**開始時間的本機日期**，不切開。月份歸屬同理。
- 所有日期判斷都用本機時區；時區計算要可注入，以便測試用固定時區。

## 7. 紀錄視窗

- 上方：月份切換（上一月／下一月／本月）、客戶篩選、專案篩選。選了客戶後專案選單只列該客戶的專案（含已封存）。被篩選的客戶或專案被刪掉時自動回到「全部」。
- 左欄：本月合計與每個專案的小計（依目前篩選），每個數字同時顯示「1h 30m」和「1.50」。
- 右欄：依日期分組，**最新日期在上，同一天內最新在上**。每筆顯示：起訖時間、標題、專案（含客戶與色點）、**完整內容不截斷**（行首「- 」顯示成項目符號點）、時長；暫停過的加小字「另暫停 20m」；正在計時的顯示「計時中」或「暫停中」與即時時長。
- 新增紀錄：手動補登，開同一個編輯視窗（新增模式）。
- 匯出 CSV：匯出目前畫面上的月份與篩選結果，用存檔對話框，預設檔名 `partimer-YYYY-MM.csv`〔設計者決定〕。

### 7.1 編輯視窗

欄位：專案、開始、結束、暫停分鐘、標題、內容（大文字框）。按儲存才寫入，按取消或關閉不寫入。

驗證（不通過就顯示原因、不寫入）：

- 結束必須晚於開始。
- 暫停分鐘 ≥ 0，且 ≤ 整段長度（結束 − 開始）。
- 已結束的紀錄不能改回計時中。
- 計時中的那筆有「仍在計時」開關（預設開）；關掉並填結束時間 = 幫它結束（若正在暫停，以填的結束時間為準，`pauseStartedAt` 清空）。開著時不能填結束時間。
- 補登與編輯都不能讓「計時中的紀錄」超過一筆。
- 補登或編輯造成的時段重疊：允許，不擋〔設計者決定〕。
- 刪除：先確認再刪。

## 9. 資料

### 9.1 位置

`<系統應用程式資料夾>/partimer/`：

- macOS：`~/Library/Application Support/partimer/`
- Windows：`%APPDATA%\partimer\`
- Ubuntu：`~/.local/share/partimer/`
- Windows 免安裝版（2026-11-07 加入）：`partimer.exe` 旁邊有 `partimer-data` 資料夾時，改用該資料夾（WebView2 的資料也放在其中的 `webview/`）；資料夾無法寫入時面板提示。

資料夾內容：

| 檔案 | 用途 |
|---|---|
| `data.json` | 主資料檔 |
| `data.json.tmp` | 原子寫入用暫存檔 |
| `backups/data-YYYY-MM-DD.json` | 每天第一次啟動時的備份，保留最近 30 份〔設計者決定〕 |
| `data.corrupt-YYYYMMDD-HHMMSS.json` | 壞檔改名保留 |
| `activity.log` | 活動紀錄 |

### 9.2 結構

```jsonc
{
  "version": 1,
  "clients":  [{ "id": "uuid", "name": "王小明", "archived": false }],
  "projects": [{ "id": "uuid", "clientId": "uuid", "name": "官網改版", "color": 0, "archived": false }],
  "entries":  [{
    "id": "uuid",
    "projectId": "uuid",
    "start": "2026-10-06T01:30:00Z",        // UTC，RFC 3339
    "end": null,                             // null = 計時中
    "title": "首頁切版",
    "content": "- 改 banner\n- 修 RWD",
    "pausedSeconds": 0,
    "pauseStartedAt": null                   // null = 沒在暫停
  }],
  "settings": {
    "lastProjectId": "uuid",
    "widget": { "enabled": true, "opacity": 0.6, "showWhenIdle": false, "x": 1200, "y": 80 },
    "hourlyReminder": false
  }
}
```

- 時間一律存 UTC，顯示與日期判斷用本機時區。
- `color` 為 0–7 的色票索引，色票由程式定義。
- 欄位名稱與型別細節〔實作者決定〕，但上面列出的資訊都要有。

### 9.3 讀寫規則

- **每次變更都整檔寫入**，用原子寫入：寫 `data.json.tmp` → flush（fsync）→ 置換成 `data.json`（Windows 也要能置換既有檔）。
- **每天第一次啟動**：把現有 `data.json` 複製到 `backups/data-<今天>.json`（今天已有就不重複）。
- **app 持續執行跨日時**：本機日期改變後的第一次存檔前，也做一次當天備份〔設計者決定，app 常駐系統匣可能數週不重啟，只在啟動時備份會讓備份過舊〕。
- **讀檔時欄位缺少**：用預設值補（例如舊版沒有 `pausedSeconds`、`pauseStartedAt`、`archived`、`color`、`settings`）。不要因少欄位就判定壞檔。
- **讀檔失敗（JSON 壞掉）**：不覆蓋原檔 → 把壞檔改名為 `data.corrupt-<時間>.json` → 從最新的可讀備份載入 → **立刻把還原的資料寫回 `data.json`** → 面板顯示提示「資料檔損壞，已從 YYYY-MM-DD 的備份還原，壞檔保留為 …」。
- **資料檔不見但有備份**：從最新備份還原、寫回、提示。
- 資料檔不見也沒有備份：當作第一次使用，建立空資料。
- 壞檔且沒有任何可讀備份：壞檔改名保留，以空資料啟動，面板顯示明顯警告〔設計者決定〕。
- 讀到不合理的資料（例如多筆計時中）：〔實作者決定修正方式〕，但不可丟失紀錄，並在活動紀錄留下說明。
- **存檔失敗**（磁碟滿、沒權限）：變更留在記憶體、面板顯示錯誤、**每秒自動重試**直到成功，app 不可當掉；成功後提示消失。

### 9.4 活動紀錄 `activity.log`

只追加，一行一筆，**不記文字內容**：

```
2026-11-06T14:05:00+08:00	START	ab12cd34	start=2026-11-06T14:05:00+08:00	end=-	title_len=4	content_len=0
```

欄位：本機時間、動作、紀錄 id 前 8 碼、起、訖、標題字數、內容字數。動作至少包含：START、PAUSE、RESUME、STOP、SAVE（存標題內容）、EDIT、ADD（補登）、DELETE；另外記錄 RESTORE（從備份還原）、SWITCH（切換專案）、AUTO_STOP（12 小時提醒的結束）〔設計者決定〕。寫入失敗不影響主流程。

## 10. CSV 格式

- UTF-8 含 BOM，換行 CRLF。
- 依開始時間由早到晚。計時中的不匯出。
- 欄位：

```
日期,客戶,專案,開始,結束,分鐘,小時,暫停分鐘,標題,內容
2026-10-06,王小明,官網改版,09:30,11:00,90,1.50,0,首頁切版,改 banner
```

- 日期、開始、結束用本機時區；結束若跨日，仍只寫 `HH:MM`〔設計者決定，日期欄已是開始日〕。
- 分鐘 = 時長四捨五入到分鐘；小時 = 分鐘 ÷ 60 四捨五入兩位；暫停分鐘 = 累計暫停四捨五入到分鐘。
- 欄位含逗號、雙引號、換行（CR 或 LF）時，整欄以雙引號包住，內部雙引號重複一次（RFC 4180）。

## 12. 架構與測試

### 12.1 結構〔設計者決定，細節由實作者調整〕

```
partimer/
├─ crates/partimer-core/   # 純 Rust：資料模型、存讀檔、備份還原、計時暫停、統計、CSV、活動紀錄
├─ src-tauri/              # Tauri 殼：系統匣、視窗、快捷鍵、單一實例、自動啟動，呼叫 core
├─ src/                    # Svelte 前端：面板、浮動小時鐘、紀錄、設定、編輯
├─ docs/
└─ .github/workflows/
```

- core 不碰 Tauri、不讀系統時間與時區：「現在」與時區由呼叫端注入（trait 或參數），方便測試。
- core 的檔案操作要能注入失敗（例如以 trait 抽象檔案系統，或以唯讀資料夾模擬），以測試存檔失敗。

### 12.2 自動化測試（core，必須全部有）

- 開始、暫停、繼續、多次暫停的時長。
- 暫停中結束：結束時間 = 暫停起點。
- 時鐘倒退時時長不為負。
- 跨午夜、月底跨月（固定時區，至少 `Asia/Taipei` 與一個有夏令時間的時區）歸屬到開始那天／那月。
- 同時最多一筆計時中。
- 少欄位的舊檔可讀，補上預設值。
- 壞檔：改名保留、從備份還原、立即寫回、回報提示。資料檔不見但有備份。
- 原子寫入；存檔失敗時資料留在記憶體、可重試成功。
- 每日備份只做一次、保留數量。
- 統計：每筆四捨五入到分鐘後加總、小數小時兩位。
- CSV：BOM、CRLF、排序、不含計時中、逗號／引號／換行跳脫、本機時區。
- 刪除專案連同紀錄、刪除客戶連同專案與紀錄、刪除數量與時間統計。
- 編輯驗證規則（§7.1）。
- 活動紀錄格式不含文字內容。

### 12.3 開發紀律

- 每次改完先跑測試；測試或編譯失敗就停下來修，不往下做、不提交。
- 前端 TypeScript 型別檢查也要過。
- 畫面與平台行為無法自動驗證的部分，列入 §13，請使用者實機操作回報，不可寫「應該沒問題」。
