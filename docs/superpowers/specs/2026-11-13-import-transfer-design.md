# 資料轉移（轉出／轉入）與匯入 CSV 設計文件

- 日期：2026-11-13
- 狀態：待使用者審閱
- 標示說明：**〔使用者決定〕** 是使用者明確說的；**〔設計者決定〕** 是撰寫者的判斷，使用者可推翻；**〔實作者決定〕** 留給實作者自行判斷。
- 前一份設計：`docs/superpowers/specs/2026-11-06-partimer-design.md`（以下稱「主設計」）。本文未提到的規則一律沿用主設計。

---

## 1. 為什麼要做

使用者要把資料從一台電腦搬到另一台（換電腦、重灌）〔使用者決定〕。搬進去的那台電腦上的 app 原本是空的〔使用者決定〕。

目前唯一的方式是「結束 app → 手動複製資料夾 → 放到新電腦的同一個位置」，使用者得自己找隱藏資料夾，Windows／macOS／Ubuntu 的路徑還都不一樣。

主設計 §1 寫的「不匯入前一版的資料」仍然成立。本文的匯入只讀**本 app 自己產生**的檔案。

## 2. 要做的兩個功能

使用者選了「兩個都做」〔使用者決定〕：

1. **資料轉移**（主要方式）：舊電腦「轉出資料」產生一個轉移檔，新電腦「轉入資料」，完整覆蓋新電腦上的所有資料。完全不掉資料。
2. **匯入 CSV**（備案）：把紀錄視窗「匯出 CSV」產生的檔案讀回來。給「舊電腦已經不在、手上只剩以前匯出的 CSV」的情況用。

### 目標

- 轉移後，新電腦上的客戶、專案、紀錄、顏色、封存狀態、設定都和舊電腦一樣，時間精確到秒。
- CSV 匯入後，每筆紀錄的日期、客戶、專案、開始、結束、暫停、標題、內容和 CSV 上寫的一致（精度到分鐘）。
- 匯入失敗時資料完全不變，並用中文說明是哪個檔案、第幾行、哪一欄出了什麼問題。

### 不做（非目標）

- 合併兩台電腦的資料（兩台都記了一陣子，要合在一起）。
- 匯入前一版 app、其他計時工具或任意格式的 CSV。
- 匯入在 Excel 裡改過、另存成其他格式的 CSV（例如 Big5 編碼、日期變成 `2026/10/6`）。遇到時要明確報錯，不用嘗試修正〔設計者決定〕。
- 雲端同步、自動轉移。

### 反目標（做到了也算失敗的情況）

- 匯入到一半失敗，留下一半的資料。
- 匯入覆蓋了原本的資料，卻沒辦法還原。
- 同一筆紀錄被匯入成兩筆。
- 匯入過程讓 app 當掉，或讓計時中的那筆壞掉。

## 3. 做法比較

| 做法 | 內容 | 取捨 |
|---|---|---|
| A. 只做 CSV 匯入 | 讀回匯出的 CSV | 只剩 CSV 也能用；但秒數、顏色、封存、設定會掉，跨日要用推的，一個月一個檔 |
| B. 只做資料轉移 | 轉出／轉入完整的轉移檔 | 完全不掉資料；但舊電腦要還能開這版 app，只剩 CSV 就救不回來 |
| **C. 兩個都做（採用）** | B 當主要方式，A 當備案 | 兩種情況都能處理；工作量約 A 的 1.5 倍 |

設計者推薦 B，使用者選 C〔使用者決定〕。

## 4. 資料轉移（轉出／轉入）

### 4.0 名稱

「匯出」「匯入」只用在 CSV（原本的「匯出 CSV」和新增的「匯入 CSV」）。資料轉移用另一組詞〔使用者決定要另外命名；以下詞彙是設計者決定〕：

| 用途 | 名稱 |
|---|---|
| 舊電腦產生轉移檔 | **轉出資料** |
| 新電腦讀入轉移檔 | **轉入資料** |
| 產生的檔案 | **轉移檔**，預設檔名 `partimer-transfer-YYYY-MM-DD.json` |
| 設定視窗區塊內的小標 | 換電腦 |
| 活動紀錄動作 | `TRANSFER_OUT`、`TRANSFER_IN` |

程式內部的函式、command 名稱也用 transfer，不用 export／import，避免和 CSV 混淆〔設計者決定〕。

### 4.1 轉出資料

- 位置：設定視窗「資料」區塊，「打開資料夾」下方加小標「換電腦」與按鈕 **「轉出資料」**〔設計者決定〕。
- 按下後跳存檔對話框，標題「轉出資料」，預設檔名 `partimer-transfer-YYYY-MM-DD.json`（本機日期），篩選器只列 `.json`。
- 檔案內容：當下記憶體中的資料，用跟 `data.json` 完全相同的格式（`model::to_json`）寫出。包含被隔離的項目（`quarantined_*`）、未知欄位（`extra`）與全部設定，一個都不丟。
- **計時中不能轉出**：計時中（含暫停中）按下會顯示「請先按 STOP 結束計時再轉出」，不跳對話框〔設計者決定，理由：計時中的那筆搬到新電腦後會繼續計時，搬家途中的時間會被算進工時〕。
- 因為計時中不能轉出，不會有未存的紀錄文字；STOP 後殘留的草稿不屬於任何紀錄，不轉出。
- 寫檔失敗沿用 CSV 匯出的中文錯誤訊息格式。
- 活動紀錄加一行 `TRANSFER_OUT`，記錄紀錄筆數。

### 4.2 轉入資料

**完整轉移、覆蓋目前所有資料**〔使用者決定〕：轉入後，這台電腦的客戶、專案、紀錄、設定和轉移檔完全相同，原本的資料（包括計時中的那筆）全部被取代，不合併。

- 位置：同一區塊，按鈕 **「轉入資料」**。
- 按下後跳開檔對話框，標題「轉入資料」，只能選一個 `.json` 檔。
- 讀檔與檢查（全部在寫入任何東西之前做完）：
  - 用 `model::parse_data` 解析；解析失敗 → 「這不是打工人計時器的轉移檔，或檔案已損壞」。`parse_data` 會把 `{}` 或任何不相干的 JSON 物件當成空資料接受，所以轉入時要另外檢查：最上層必須有數字 `version`，以及 `clients`、`projects`、`entries` 三個陣列（`to_json` 一定會寫出這些）。少了任何一個也算「不是轉移檔」〔設計者決定〕。
  - `version` 比目前 app 新 → 「這個轉移檔來自較新版的打工人計時器，請先更新 app」。
  - 檔案裡有計時中或暫停中的紀錄（`end` 為 null）→ 拒絕，說明「轉移檔裡有一筆還在計時，請在舊電腦按 STOP 後重新轉出」〔設計者決定〕。
- 確認對話框一律顯示〔設計者決定〕：
  - 「將轉入 X 個客戶、Y 個專案、Z 筆紀錄（YYYY-MM-DD ～ YYYY-MM-DD）。」
  - 這台電腦有任何資料時加上：「這台電腦目前的 N 個客戶、M 個專案、K 筆紀錄會全部被取代。原本的資料會另存為 `data.before-transfer-YYYYMMDD-HHMMSS.json`。」計時中再加「計時中的那筆也會被取代」。
- 確認後：
  1. 把目前**記憶體中**的資料用 `to_json` 寫成 `data.before-transfer-YYYYMMDD-HHMMSS.json`（放在資料夾根目錄，和 `data.corrupt-…` 同一層）。要用記憶體中的資料、不能直接複製 `data.json`，因為存檔失敗正在重試時，兩者內容不同〔設計者決定〕。寫入失敗就中止，資料不變。記憶體中的資料完全是空的（沒有客戶、專案、紀錄、隔離項目）就略過這步。
  2. 用轉移檔的資料**整份**取代記憶體中的資料，包括所有設定（浮動小時鐘的開關、透明度、位置，整點提醒，最後選的專案）。小時鐘位置不用特別處理：`windows.rs` 已經會在儲存的位置不在任何螢幕上時，改放到主螢幕右上角（有測試 `widget_saved_position_off_every_screen_falls_back_to_top_right`）。
  3. 計時中的話，計時直接結束、不留下那一筆（它已經在步驟 1 另存了），面板回到未計時狀態〔設計者決定〕。不要寫 STOP 的活動紀錄，避免看起來像使用者按了 STOP。
  4. 用主設計 §9.3 的原子寫入存檔。存檔失敗沿用主設計「留在記憶體、每秒重試」。
  5. 所有視窗重新整理（面板的專案選單與今日紀錄、紀錄視窗、設定視窗的客戶專案列表與各項設定、浮動小時鐘的顯示與位置）。
  6. 面板上的草稿清空；最後選的專案若不存在就回到未選狀態〔實作者決定細節〕。
  7. 活動紀錄加一行 `TRANSFER_IN`，記錄轉入的筆數、被取代的筆數與另存檔名。
- 開機自動啟動、全域快捷鍵不在資料檔裡，不受影響。

## 5. 匯入 CSV

### 5.1 入口與條件

- 位置：紀錄視窗「匯出 CSV」旁加按鈕 **「匯入 CSV」**〔設計者決定〕。
- 開檔對話框**可一次選多個** `.csv` 檔（CSV 是一個月一個檔）〔設計者決定〕。
- **只在沒有任何紀錄時能用**〔使用者決定新電腦是空的；設計者決定擋下非空的情況，因為 CSV 沒有紀錄編號，無法判斷哪些已經存在〕。被隔離的紀錄（`quarantined_entries`）也算紀錄〔設計者決定，比較保守〕。已有紀錄時顯示「匯入 CSV 只能用在還沒有任何紀錄的時候。要在兩台電腦間搬資料，請改用設定裡的『轉入資料』」。客戶、專案已經存在沒關係。

### 5.2 檔案格式檢查

必須是本 app 匯出的格式（主設計 §10），否則整批不匯入：

- UTF-8，有沒有 BOM 都接受；換行 CRLF 或 LF 都接受〔設計者決定〕。不是合法 UTF-8 → 「檔案不是 UTF-8 編碼，可能被 Excel 另存過」。
- 第一行必須完全等於表頭 `日期,客戶,專案,開始,結束,分鐘,小時,暫停分鐘,標題,內容`。
- 引號規則照 RFC 4180（雙引號包住、內部雙引號重複），欄位內可含逗號與換行。要自己寫解析器，**不加新套件**（主設計 §2 的套件清單外需另外詢問）。
- 每一列剛好 10 欄。
- **還原防公式注入的 TAB**：`report::csv_field` 匯出時，會在以 `=`、`+`、`-`、`@`、TAB、CR 開頭的欄位前面加一個 TAB，而且這種欄位一定加引號。客戶、專案、標題、內容四欄都會這樣處理。匯入時，有引號的欄位如果以 TAB 開頭、TAB 後面的字元又是上述其中之一，就去掉這一個 TAB〔設計者決定，這樣剛好是匯出的反向操作〕。不去掉的話，名稱會對不到既有的客戶專案，往返測試也會失敗。
- 日期 `YYYY-MM-DD`；開始、結束 `HH:MM`（24 小時制）；分鐘、暫停分鐘是 ≥ 0 的整數；「小時」欄不讀（由分鐘算得出來）。
- 空白行略過。
- 任何一列不合格 → 整批不匯入，錯誤訊息寫「`partimer-2026-10.csv` 第 12 行：開始時間『9:3』格式不對，應為 HH:MM」。錯誤多筆時最多列前 5 筆加「…還有 N 筆」〔設計者決定〕。

### 5.3 每列轉成一筆紀錄

時區：用**匯入這台電腦的本機時區**解讀日期與時間〔設計者決定；CSV 沒記時區，換到不同時區的電腦會偏掉，在確認對話框註明〕。

- `start` = 本機時間（日期, 開始）轉 UTC。
- `end`：CSV 只寫 `HH:MM`、不寫日期。取「日期 + k 天 的 結束時間」，k ≥ 0，選讓 `end − start` **最接近「分鐘 + 暫停分鐘」** 的那個 k〔設計者決定；這樣跨日、甚至超過 24 小時的紀錄也能還原正確的日期〕。
- `paused_seconds` = 暫停分鐘 × 60；`pause_started_at` = null。
- `title`、`content` 原樣保留（含換行）。
- 本機時間落在夏令時間**重複**的時段（同一個時刻有兩個 UTC 時間）：開始、結束的每種可能時間都和每個 k 組合試一次，取 `end − start` 最接近「分鐘 + 暫停分鐘」的組合〔設計者決定；`zone.rs` 目前固定取較早的時間，用在這裡會差 60 分鐘，害整批被下面的 2 分鐘檢查擋掉〕。落在**跳過**的時段（該時刻不存在）：〔實作者決定〕，與 `zone.rs` 一致。
- 秒數一律為 0。因為開始、結束、暫停都各自四捨五入過，匯入後算出的分鐘數可能和 CSV「分鐘」欄差 1 分鐘，這是預期的，不報錯〔設計者決定〕。用上面的方式選好時間後，仍然差超過 2 分鐘，就視為格式錯誤（代表檔案被改過）〔設計者決定〕。

### 5.4 客戶與專案

- 依**名稱**對應（比對前去掉頭尾空白，和 `catalog::add_project` 的規則一致）。
  - 同名客戶已存在就用它；不存在就新建。
  - 該客戶底下同名專案已存在就用它（包含已封存的）；不存在就新建。
- 新建的專案顏色依建立順序輪流用 0–7〔設計者決定〕。
- 客戶或專案名稱是空的（匯出時專案已被刪掉才會出現）→ 用「未命名客戶」／「未命名專案」〔設計者決定〕。

### 5.5 重複列

多個檔案可能重疊（同一個月匯出兩次、選到同一個檔兩次）。**10 欄全部相同**的列只匯入一筆，略過的數量在確認對話框顯示〔設計者決定〕。

### 5.6 確認與寫入

- 解析全部成功後先顯示確認：「將匯入 Z 筆紀錄（YYYY-MM-DD ～ YYYY-MM-DD），新增 X 個客戶、Y 個專案；略過重複 W 筆。時間依這台電腦的時區解讀。」
- 確認後：
  1. 記憶體中有客戶或專案時，先另存 `data.before-import-YYYYMMDD-HHMMSS.json`（做法同 §4.2 步驟 1，從記憶體寫出），失敗就中止。
  2. 一次把所有客戶、專案、紀錄加進記憶體中的資料，原子寫入存檔。
  3. 所有視窗重新整理。
  4. 活動紀錄加一行 `IMPORT_CSV`，記錄檔案數、匯入筆數、略過筆數。不需要每筆一行〔設計者決定〕。

## 6. 共通規則

- **全有或全無**：所有檢查都在改動資料之前完成；中途任何一步失敗，記憶體與檔案都維持原狀。
- **改動前另存**：轉入資料前留 `data.before-transfer-…json`，匯入 CSV 前留 `data.before-import-…json`。這類檔案不自動清理，README 說明可以手動刪〔設計者決定〕。它們的格式和轉移檔相同，所以要回到轉入或匯入前的狀態，用「轉入資料」選這個檔就好。
- **禁止存檔時不能轉入或匯入**：`data.json` 來自較新版、或讀不到而進入禁止存檔狀態時（`Loaded::save_blocked`），轉入資料與匯入 CSV 都拒絕，訊息沿用目前禁止存檔的說明〔設計者決定，維持「禁止存檔時絕不寫 `data.json`」的規則〕。轉出資料不受影響。
- 對話框（開檔、存檔、確認）沿用 `tauri-plugin-dialog`，需要在 capabilities 加開檔／存檔權限〔實作者決定細節〕。
- 錯誤訊息一律中文，原始（英文）錯誤放括號裡，沿用 `export_error` 的格式。
- 核心邏輯（CSV 解析、轉換、合併、資料取代與保留欄位）放在 `partimer-core`，不依賴 Tauri；Tauri 層只負責對話框與呼叫。

## 7. 測試（core，必須有）

- 資料轉移：轉出 → 轉入到有資料（含計時中）的另一份資料後，兩者完全相等（含設定、`extra`、`quarantined_*`）；計時中被取代時不留下那筆、不寫 STOP；計時中不能轉出；拒絕較新 version、拒絕有計時中的轉移檔、拒絕 `{}` 與缺陣列的 JSON、拒絕壞檔；另存失敗時資料不變；另存檔可以再轉入還原。
- CSV 往返：用 `export_csv` 匯出多個月 → 匯入到空資料 → 每筆的本機日期、開始、結束（到分鐘）、暫停分鐘、標題、內容、客戶、專案名稱和原本一致；`export_csv` 再匯出一次，內容和第一次完全相同（「小時」與「分鐘」欄允許 §5.3 的 1 分鐘差異時要另外說明）〔實作者決定斷言方式〕。
- 跨日、超過 24 小時、跨月最後一天、夏令時間（用 `chrono-tz` 測）的紀錄。
- 有 BOM／沒 BOM、CRLF／LF、欄位含逗號、雙引號、換行。
- 表頭不對、欄數不對、日期／時間格式不對、非 UTF-8 → 錯誤訊息指出檔名與行號，資料不變。
- 已有紀錄時拒絕 CSV 匯入；只有客戶專案時可以匯入，同名對應正確（含已封存專案）。
- 重複列只匯入一筆。
